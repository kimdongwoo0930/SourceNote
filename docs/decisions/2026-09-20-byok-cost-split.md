# 추론 비용을 사용자 API 키로 분리 (BYOK)

- **날짜**: 2026-09-20
- **상태**: 확정
- **관련**: [COST_OPTIMIZATION.md](../COST_OPTIMIZATION.md), [ARCHITECTURE.md](../ARCHITECTURE.md)

## 배경

외부 API 비용이 두 갈래로 발생한다. 임베딩은 문서를 넣을 때 한 번, 추론(질문답변·문제생성)은 사용자가 쓸 때마다다. 1인 개인 프로젝트에서 후자를 개발자가 부담하면 사용자 수와 사용량에 비례해 비용이 무한히 늘어난다.

## 선택지

1. 전부 개발자 부담 — 사용 한도(쿼터)로 방어
2. 전부 사용자 부담 — 임베딩까지 사용자 키
3. **임베딩은 개발자, 추론은 사용자 키 (BYOK)**

## 결정

3번. 임베딩은 서버 고정 키로 처리하고, 질문답변·문제생성은 사용자가 설정에서 등록한 Claude 또는 GPT 키로 호출한다.

## 근거

- 단가 차이가 자릿수로 다르다. 100페이지 임베딩 ≈ 2원 / 질문 1회 0.8~13원.
- 임베딩은 자료 양에 비례해 **유한**하지만 추론은 `사용자 수 × 호출 수`로 **무한**하다.
- 1번(쿼터)은 "무료지만 쓸 수 없는 서비스"가 되고, 쿼터 관리 코드가 추가로 필요하다.
- 2번은 임베딩 키까지 사용자가 등록해야 하고, 저장·검색 임베딩 모델이 사용자마다 달라지면 벡터 공간이 섞여 검색이 깨진다. 임베딩 모델은 서버가 고정해야 한다.

## 트레이드오프

대중 서비스로서는 나쁜 선택이다. 일반 사용자에게 API 키 발급을 요구하면 전환율이 사실상 0이다. **이 프로젝트의 목표가 사용자 확보가 아니라 멀티유저·인증·비용 분리 설계를 완성하는 것**이므로 감수한다. 오히려 아래 문제들을 실제로 풀어야 해서 설계 밀도가 올라간다.

## 영향

- `Settings`에 provider·암호화된 API 키·모델 저장, 응답에서는 마스킹
- provider·key·model이 요청마다 달라 **ChatModel을 고정 빈으로 둘 수 없음** → 요청 시점 생성
- 키 검증 겸 모델 목록 조회를 사용자 키로 제공사 `/v1/models` 호출 (Anthropic `x-api-key`, OpenAI `Bearer`)
- `LlmUsageLog.operation_type`으로 개발자 부담(임베딩)과 사용자 부담(추론) 비용을 분리 집계
- 키를 등록하지 않은 사용자는 질문하기·문제풀기를 쓸 수 없다 (자료 업로드는 가능)
