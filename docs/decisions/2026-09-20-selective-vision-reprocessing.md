# 비전 모델 재처리를 저품질 페이지로 한정

- **날짜**: 2026-09-20
- **상태**: 확정
- **관련**: [ARCHITECTURE.md](../ARCHITECTURE.md#문서-처리-파이프라인)

## 배경

전공서 PDF는 수식·표·그림 캡션이 많아 Tika/PDFBox 텍스트 추출이 **부분적으로** 깨진다. 깨진 텍스트를 그대로 임베딩하면 검색은 되지만 답변의 근거로 쓸 수 없게 된다.

## 선택지

1. 텍스트 추출만 사용 — 깨진 페이지는 포기
2. 전체 페이지를 비전 모델로 처리
3. **페이지별 품질을 검사해 미달 페이지만 비전 모델로 재처리**

## 결정

3번. 페이지 단위로 깨진 문자 비율과 텍스트 분량을 검사하고, 기준 미달 페이지만 비전 모델에 넘긴다.

## 근거

- 2번은 비용이 자릿수로 뛴다. 전공서 한 권이 수백 페이지인데, 대부분 페이지는 일반 추출로 충분하다.
- 품질 판단을 **문서 단위가 아니라 페이지 단위**로 해야 한다. 한 권에서 수식이 몰린 몇 페이지만 깨지는 것이 일반적이라, 문서 전체를 하나로 판단하면 과잉 재처리(문서 전체 비전 처리)나 과소 처리(깨진 페이지 방치) 중 하나가 된다.
- 1번은 하필 시험에 나오는 수식·표 페이지를 버리게 된다.

## 트레이드오프

품질 판정 임계값이 휴리스틱이다. 너무 느슨하면 깨진 페이지가 통과하고, 너무 엄격하면 비용이 늘어난다. 초기값으로 시작해 실제 전공서 샘플로 조정하고, 조정 결과는 이 파일에 덧붙인다.

## 영향

- 파이프라인이 페이지 경계를 유지해야 한다 (청킹 전까지 페이지 단위 보존)
- `page_number`가 Qdrant payload에 들어가 출처 표시에 쓰인다
- 비전 모델 호출도 비용이므로 `LlmUsageLog`에 기록한다
- PDF 업로드는 비전 재처리 때문에 처리 시간이 길어질 수 있어 **비동기 처리 + 상태 폴링**이 필수다
